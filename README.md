# X 정리 도구 (X Cleanup)

내 X(트위터) 게시물·답글, 좋아요, 북마크를 정리하는 정적 웹사이트입니다. GitHub Pages에 올려서 사용하도록 만들었고, X API는 쓰지 않습니다.

## 동작 방식

브라우저 보안 규칙(cross-origin) 때문에 GitHub Pages 사이트가 x.com에 직접 요청을 보낼 수 없습니다. 그래서 역할을 둘로 나눴습니다.

| 단계 | 어디서 | 하는 일 |
| --- | --- | --- |
| 1~3 | 이 웹사이트 | X에서 내려받은 아카이브(zip)를 **브라우저 안에서만** 읽고, 지울 대상을 고르고, 백업과 작업 파일(`xclean-job-*.json`)을 만듭니다. |
| 4 | x.com 탭 | 로그인된 x.com 탭의 개발자 도구 콘솔에 `runner.js`를 붙여넣고 작업 파일을 선택하면, 그 탭 안에서 삭제/좋아요 취소가 실행됩니다. |

아카이브와 작업 파일은 어떤 서버로도 전송되지 않습니다. 사이트의 CSP가 `connect-src 'self'`라서 외부 요청 자체가 차단됩니다.

## 배포 (GitHub Pages)

1. GitHub에서 새 저장소를 만들고 이 폴더의 파일을 모두 올립니다.
2. 저장소 **Settings → Pages → Build and deployment**에서 `Deploy from a branch`, 브랜치 `main`, 폴더 `/ (root)`를 선택합니다.
3. 1~2분 뒤 `https://<계정>.github.io/<저장소>/`에서 열립니다.

빌드 과정은 없습니다. `.nojekyll` 파일이 포함되어 있습니다.

## 사용 순서

1. X 설정 → 내 계정 → **데이터 보관소 다운로드**를 요청하고, 받은 zip을 사이트에 올립니다 (`tweets.js`, `like.js`, `tweet-headers.js` 등만 읽습니다. 대용량 zip/ZIP64 지원).
2. 탭에서 게시물/좋아요/북마크 대상을 고릅니다. 종류, 기간, 포함·제외 단어, 좋아요 수 보존, 보호 목록(ID/URL)과 미리보기에서 개별 체크 해제가 가능합니다.
3. 백업(JSON/CSV)을 내려받고, 확인란을 체크한 뒤 작업 파일을 만듭니다.
4. x.com에 로그인한 탭에서 `F12` → Console에 `runner.js` 내용을 붙여넣습니다 (사이트의 "실행기 복사" 버튼 사용). 패널에서 작업 파일을 선택하고 속도를 고른 뒤 시작합니다.

실행 중에는 탭을 닫거나 새로고침하지 마세요. 진행 상황은 브라우저 localStorage에 저장되어, 같은 작업 파일을 다시 불러오면 이어서 진행합니다.

## 작업 파일 형식

```json
{
  "format": "xclean-job",
  "version": 1,
  "id": "a1b2c3d4e5f6",
  "createdAt": "2026-01-01T00:00:00.000Z",
  "tweets": ["1234567890123456789"],
  "likes": ["1234567890123456789"],
  "bookmarksAll": false
}
```

ID는 문자열입니다 (2^53을 넘는 값이 있기 때문입니다).

## 알아둘 점

- **되돌릴 수 없습니다.** 삭제한 게시물과 취소한 좋아요는 복구되지 않습니다. 백업을 먼저 받으세요.
- **계정 제한 위험이 있습니다.** 실행기는 X 웹앱의 비공개(내부) GraphQL 엔드포인트를 사용합니다. 자동화는 X 약관에 어긋날 수 있고, 계정이 일시 제한될 수 있습니다. 기본 속도(안전)를 권장합니다.
- **X가 내부 구조를 바꾸면 작동하지 않을 수 있습니다.** 실행기는 페이지 자체 요청과 JS 번들에서 `queryId`를 찾아 쓰고, 못 찾을 때만 코드에 들어 있는 대체값을 씁니다. 대체값은 오래되었을 수 있습니다.
- **북마크는 전체 삭제만 지원합니다.** 개별 선택 삭제는 하지 않습니다. 실행기의 "북마크 백업"으로 먼저 저장할 수 있습니다.
- **오래된 좋아요는 취소가 실패할 수 있습니다.** X 쪽에서 이미 접근할 수 없는 게시물이 있습니다.
- 아카이브에 북마크는 들어 있지 않습니다.

## 테스트

모의 데이터와 모의 x.com으로만 검증했습니다. 실제 X 계정에서는 테스트하지 않았습니다.

```sh
python3 tests/make-fixtures.py <fixtures 폴더>
node --test tests/core.test.js
node tests/e2e-site.cjs <fixtures 폴더> <스크린샷 폴더>     # Playwright 필요
node tests/e2e-runner.cjs                                       # Playwright 필요
```

## 파일 구성

- `index.html`, `css/style.css`, `js/core.js`, `js/app.js` — 웹사이트
- `runner.js` — x.com 콘솔용 실행기
- `tests/` — 단위/E2E 테스트
