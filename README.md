# X 정리 도구 (X Cleanup)

내 X(트위터) 게시물·답글, 좋아요, 북마크를 정리하는 정적 웹사이트입니다. GitHub Pages에 올려서 사용하도록 만들었고, X API는 쓰지 않습니다.

## 동작 방식

브라우저 보안 규칙(cross-origin) 때문에 GitHub Pages 사이트가 x.com에 직접 요청을 보낼 수 없습니다. 그래서 역할을 둘로 나눴습니다.

| 단계 | 어디서 | 하는 일 |
| --- | --- | --- |
| 1~3 | 이 웹사이트 | X에서 내려받은 아카이브(zip)를 **브라우저 안에서만** 읽고, 지울 대상을 고르고, 백업과 작업 파일(`xclean-job-*.json`)을 만듭니다. |
| 4 | x.com 탭 | 로그인된 x.com 탭의 개발자 도구 콘솔에 `runner.js`를 붙여넣고 작업 파일을 선택하면, 실행기가 그 탭에서 게시물 화면을 하나씩 열고 사람이 누르는 버튼(⋯ → 삭제하기 → 확인, 하트, 북마크)을 자동으로 누릅니다. |

아카이브와 작업 파일은 어떤 서버로도 전송되지 않습니다. 사이트의 CSP가 `connect-src 'self'`라서 외부 요청 자체가 차단됩니다.

## 배포 (GitHub Pages)

1. GitHub에서 새 저장소를 만들고 이 폴더의 파일을 모두 올립니다.
2. 저장소 **Settings → Pages → Build and deployment**에서 `Deploy from a branch`, 브랜치 `main`, 폴더 `/ (root)`를 선택합니다.
3. 1~2분 뒤 `https://<계정>.github.io/<저장소>/`에서 열립니다.

빌드 과정은 없습니다.

## 사용 순서

### 아카이브 없이 (바로 정리)

1. x.com에 로그인한 탭에서 `F12` → Console에 `runner.js` 내용을 붙여넣습니다 (사이트의 "실행기 복사" 버튼 사용).
2. 패널의 방식에서 **바로 정리 (아카이브 없이)** 를 고르고, 정리할 항목(게시물·답글/재게시, 좋아요, 북마크)과 필요하면 "이 날짜 이전 것만"을 정합니다.
3. **시험 실행**으로 먼저 확인(단계마다 3개까지 확인 창만 열었다가 취소)한 뒤, 체크를 풀고 시작합니다.

실행기는 내 프로필(`/아이디`, `/아이디/with_replies`), `/i/history/likes`, 북마크 화면을 위에서부터 스크롤하며 처리합니다. 프로필에 보이는 범위까지만 지울 수 있습니다.

### 아카이브로 골라서 (작업 파일)

1. X 설정 → 내 계정 → **데이터 보관소 다운로드**를 요청하고, 받은 zip을 사이트에 올립니다 (`tweets.js`, `like.js`, `tweet-headers.js` 등만 읽습니다. 대용량 zip/ZIP64 지원).
2. 탭에서 게시물/좋아요/북마크 대상을 고릅니다. 종류, 기간, 포함·제외 단어, 좋아요 수 보존, 보호 목록(ID/URL)과 미리보기에서 개별 체크 해제가 가능합니다.
3. 백업(JSON/CSV)을 내려받고, 확인란을 체크한 뒤 작업 파일을 만듭니다.
4. x.com에 로그인한 탭에서 `F12` → Console에 `runner.js` 내용을 붙여넣습니다 (사이트의 "실행기 복사" 버튼 사용). 패널에서 작업 파일을 선택합니다.
5. 먼저 **시험 실행**을 체크하고 실행합니다. 실제로 지우지 않고 삭제 확인 창까지만 열었다가 취소하므로, 현재 X 화면에서 작동하는지 확인할 수 있습니다.
6. 시험 결과에 실패가 없으면 체크를 풀고 속도를 고른 뒤 시작합니다. 1건당 몇 초가 걸립니다.

실행 중에는 탭을 닫거나 새로고침하지 말고 화면에 띄워 두세요(백그라운드 탭은 브라우저가 크게 느리게 만듭니다). 진행 상황은 브라우저 localStorage에 저장되어, 같은 작업 파일을 다시 불러오면 이어서 진행합니다.

## 작업 파일 형식

```json
{
  "format": "xclean-job",
  "version": 1,
  "id": "a1b2c3d4e5f6",
  "createdAt": "2026-01-01T00:00:00.000Z",
  "tweets": ["1234567890123456789"],
  "likes": ["1234567890123456789"],
  "bookmarksAll": false
}
```

ID는 문자열입니다 (2^53을 넘는 값이 있기 때문입니다).

## 알아둘 점

- **되돌릴 수 없습니다.** 삭제한 게시물과 취소한 좋아요는 복구되지 않습니다. 백업을 먼저 받으세요.
- **계정 제한 위험이 있습니다.** 자동화는 X 약관에 어긋날 수 있고, 계정이 일시 제한될 수 있습니다. 기본 속도(보통) 이하를 권장합니다.
- **X 화면 구성이 바뀌면 작동하지 않을 수 있습니다.** 실행기는 X 화면의 `data-testid`(caret, unlike, unretweet, removeBookmark, confirmationSheetConfirm 등)와 메뉴의 "삭제하기" 항목을 찾아 누릅니다. 연속 5회 실패하면 스스로 멈추고, 실패한 항목은 다시 시도할 수 있게 되돌립니다.
- **v1에서 바뀐 점:** v1은 X 내부 GraphQL 요청을 직접 보냈지만, 2026년 11월 기준 X 웹이 요청 경로와 보안 헤더(`x-client-transaction-id`)를 바꿔 모두 거부되었습니다. v2는 요청을 직접 만들지 않고 화면 버튼을 누릅니다.
- **요청 한도(429 Too Many Requests):** 실행기는 X 화면이 보내는 요청의 응답 상태만 읽어(요청 내용은 바꾸지 않음) 429가 나오면 패널에 알림을 띄우고 자동으로 일시정지합니다. 진행 중이던 항목은 실패로 세지 않고, '재개'를 누르면 그 항목부터 다시 시도합니다. 응답에 해제 시각이 있으면 함께 보여 줍니다.
- **재게시(리트윗)** 는 '재게시 취소'로 처리합니다. 내 글이 아니고 재게시도 되어 있지 않으면 '이미 없음'으로 넘어갑니다.
- **북마크는 전체 해제만 지원합니다.** 실행기의 "북마크 백업"으로 먼저 저장할 수 있습니다.
- **삭제된 게시물에 남은 좋아요는 취소할 수 없습니다.** 화면에 게시물이 열리지 않기 때문입니다('이미 없음'으로 처리).
- 아카이브에 북마크는 들어 있지 않습니다.

## 테스트

모의 데이터와 모의 X 화면(`tests/mock-x.js`)으로 검증했습니다. 실제 X(2026-11-10)에서는 시험 실행(삭제 없이 확인 창까지)으로 게시물 삭제 메뉴·확인 창, 없는 게시물 처리, 좋아요 버튼 인식을 확인했습니다.

```sh
python3 tests/make-fixtures.py <fixtures 폴더>
node --test tests/core.test.js
node tests/e2e-site.cjs <fixtures 폴더> <스크린샷 폴더>     # Playwright 필요
node tests/e2e-runner.cjs                                       # Playwright 필요
```

## 파일 구성

- `index.html`, `css/style.css`, `js/core.js`, `js/app.js` — 웹사이트
- `runner.js` — x.com 콘솔용 실행기
- `tests/` — 단위/E2E 테스트 (`mock-x.js`: 실행기 테스트용 모의 X 화면)
